# 移动端原型设计计划

目标：在手机上演示完整打球过程，不连接真实订单、支付、AI或球场设备。用户指定使用frontend-design。

## 视觉方向
球场俱乐部的清晰服务感。森林绿 #164D3C、白 #FFFFFF、雾灰 #F4F7F5、深墨绿 #142E25、浅草绿 #E5EEE8、沙金 #B18A4D。中文使用系统苹方，标题清晰厚重，数字使用Georgia用于杆数和开球时间。正文16px，信息标签13px。强调球场摄影与球洞示意图，避免大片背景干扰。

布局：移动端单列，左对齐，底部固定五项导航：今日、订场、球局、球队、我的。桌面作为演示工作台，左侧说明与角色切换，右侧手机宽度原型；窄屏只保留原型。首页以球场实景和下一场任务建立记忆点，其余区域克制。

对比评审：UI检索返回的是体育营销方向，红色和大块动效不适合高尔夫现场服务；采用高尔夫森林绿与易读轻背景。用不同信息密度而非同型卡片堆砌。关键按钮44px以上，状态文字不只依赖颜色，减少动效。

## 演示范围
1. 今日：预约卡、快捷操作、服务进度、精选教学。
2. 订场：搜索筛选、球场详情、日期和时段、人数、费用、确认订单、改期取消、订单详情。
3. 球局：18洞、Tee、同行、单洞记分、撤销、弱网模拟、本地持久化、完成球局、数据驱动的复盘模板。
4. 球队：约球活动、邀请、报名退出、教学筛选与详情。
5. 我的：订单、历史球局、球包记录、提醒、收藏、说明与重置。
6. 球童模式：任务、装备清点与取还确认、异常提交、服务完成。
7. AI助手：示例知识库问答与赛后复盘；明确模拟性质。

## 数据与技术
初始原型为原生HTML/CSS/JavaScript静态网站，localStorage保存演示状态。后续增加Python服务、运营后台和数据库联动；当前已按用户要求迁移MySQL 5.7.43，并将目录调整为 `/www/wwwroot/gaoqiu`，迁移与服务切换验收通过。localStorage用于弱网缓存，不调用外部AI。球场、价格、时段、天气、距离和服务记录为演示数据；IP端口演示不提交真实球场预订、不扣款。
